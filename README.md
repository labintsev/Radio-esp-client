# Radio — Si4703 + PCM1808 → radio-record-server

Прошивка ESP32-S3 (DevKitC-1, модуль N16R8): тюнер Si4703 отдаёт аналоговый звук
на АЦП PCM1808, ESP32-S3 читает поток по I2S и шлёт его кадрами на
[radio-record-server](https://github.com/labintsev/radio-record-server)
(протокол `RDIO`, PCM s16le, порт 9100).

## Что где

| Файл | Назначение |
|------|------------|
| `include/config.h` | Wi-Fi, адрес сервера, пины, формат аудио |
| `src/audio_source.cpp` | I2S + преобразование 24 бита → 16 бит |
| `src/streamer.cpp` | TCP-соединение и 43-байтный заголовок кадра |
| `src/main.cpp` | Wi-Fi, тюнер, аудио-задача, статистика |

## Плата

`platformio.ini` собран под **ESP32-S3 DevKitC-1 N16R8** — 16 МБ flash + 8 МБ
PSRAM (octal), `board_build.arduino.memory_type = qio_opi`.

Занятые на S3 выводы, которые нельзя использовать в `config.h`:

| GPIO | Почему занят |
|------|--------------|
| 26–32 | SPI flash |
| 33–37 | octal-PSRAM (только у N16R8) |
| 19, 20 | нативный USB |
| 0, 3, 45, 46 | strapping-пины при старте |

В отличие от классического ESP32, MCLK на S3 можно вывести на любой GPIO —
ограничения «только GPIO0/1/3» здесь нет.

## Подключение PCM1808

Модуль PCM1808 без своего кварца — **слейв шины**: ESP32 генерирует MCLK 4.096 МГц
(256 fs), BCK 1.024 МГц и LRCK 16 кГц (`I2S_ESP32_MASTER 1`).

| PCM1808 | ESP32 | Примечание |
|---------|-------|------------|
| VCC     | 5V    | на модуле стоит LDO, логика 3.3 В |
| GND     | GND   | общая земля, аналоговую часть — к тому же GND |
| BCK     | GPIO4  | вход тактирования битов |
| LRCK    | GPIO5  | вход словного синхросигнала (16 кГц) |
| DOUT    | GPIO6  | данные от АЦП |
| SCKI    | GPIO7  | MCLK 4.096 МГц |
| FMT     | GND   | формат I2S (Philips), не left-justified |
| MD0/MD1 | GND   | slave-режим, 24 бита |

Аналог: `LOUT`/`ROUT` тюнера → `LIN`/`RIN` модуля (если на модуле нет разделительных
конденсаторов — поставить 1 мкФ последовательно), провода от цифровой части держать
подальше от аналоговых.

Тюнер Si4703 по I2C: `SDA` → GPIO8, `SCL` → GPIO9, `RST` → GPIO10, `SEN` → GND
(адрес 0x10, 3.3 В питание).

Если у модуля есть собственный кварц и он мастер — поставьте
`#define I2S_ESP32_MASTER 0`, отключите провод MCLK, а MD0/MD1 переведите в master
(BCK/LRCK при этом станут выходами модуля).

## Почему 16 кГц моно

ESP32-S3 сам генерирует SCKI = 256 fs, а PCM1808 (slave) работает от 8 до 96 кГц,
поэтому 16 кГц доступны без кварца на модуле. Стерео с АЦП сводится в моно прямо
в прошивке (`CHANNELS 1` в `config.h`), а на сервер уходит 32 кБ/с (≈256 кбит/с)
вместо 192 кБ/с у 48 кГц стерео.

Серверу эти параметры подходят по умолчанию, но их лучше указать явно:

```powershell
python -m radio_record --port 9100 --output recordings --sample-rate 16000 --channels 1
```

## Проверка без АЦП

В `include/config.h` выставить `AUDIO_SOURCE_TEST_TONE 1` — прошивка начнёт слать
синус 1 кГц вместо I2S. Удобно проверить путь «ESP32-S3 → сервер» до подключения PCM1808.

## Диагностика I2S

Измерение частот на линиях счётчиком импульсов (PCNT) по умолчанию выключено:
`pcnt_unit_config()` переводит измеряемые GPIO в режим входа и на время замера
глушит выходы BCK/LRCK/MCLK, а на ESP32-S3 результат врёт (показывает сотни герц
вместо 1.024 МГц). Включить для разового замера: `AUDIO_CLOCK_DIAG 1` в
`include/config.h` — тогда при старте печатается:

```
[i2s] MCLK 4096000 Гц, BCK 1024000 Гц, LRCK 16000 Гц
[i2s] фактическая fs 16000 Гц, 64 бит/кадр
[i2s] SCKI = 256 fs
```

Как читать:

| Вывод | Что это значит |
|-------|----------------|
| `MCLK/BCK/LRCK 0` | тактирования нет: неверные пины, ESP32-S3 не запустил APLL (см. ошибки выше) |
| `LRCK` не равен `SAMPLE_RATE` | поправить `SAMPLE_RATE` и `--sample-rate` сервера |
| `SCKI` не 256/384/512 fs | MCLK вышел не тот — PCM1808 не будет работать |
| кадры идут, `пик 0` | DOUT не подключён, АЦП молчит или нет сигнала с тюнера |
| кадры идут, `пик > 0`, но `отправлено 0` | проблема сети/сервера (см. строки `[net]`) |

При `пик 0` прошивка дополнительно печатает пины и первые сырые 32-битные слоты
(`[i2s] сырые слоты: ...`): `00000000` — линия DOUT молчит (не тот пин, нет SCKI у
PCM1808), ненулевые значения — АЦП отдаёт данные, но на его входе тишина.

`[stat]` раз в 5 секунд показывает кадры/с, пиковый уровень последнего кадра, RSSI и
свободную память; при отсутствии данных печатается отдельная подсказка.

## Диагностика тюнера

Перед настройкой частоты прошивка проверяет, что Si4703 отвечает на адресе 0x10:

```
[tuner] нет ответа на 0x10: SDA=GPIO8, SCL=GPIO9, RST=GPIO10, SEN -> GND, питание 3.3 В
[i2c] устройства на шине: нет
[tuner] настройка пропущена (иначе setFrequency() зависнет)
```

Как читать:

| Вывод | Что это значит |
|-------|----------------|
| `нет ответа на 0x10`, на шине пусто | нет проводки/питания: проверьте SDA/SCL/RST, `SEN -> GND`, 3.3 В и общую землю |
| `нет ответа на 0x10`, но в списке есть другой адрес | `SEN` поднят в HIGH — адрес `0x11`, оставьте `SEN` на GND |
| `нет ответа`, хотя всё подключено | RST приходит не на тот пин: Si4703 держит I2C выключенным до сброса |

Проверка обязательна: без ответа чипа `setFrequency()` навсегда зависает внутри
`waitAndFinishTune()` — неудачные чтения дают `0xFFFF`, а бит `STC` (0Ah[14]) в
этом случае равен 1, поэтому цикл ожидания его сброса не заканчивается.

## Что происходит при обрывах

- `first_sample` растёт монотонно всё время работы, поэтому пауза при переподключении
  выглядит для сервера как пропуск и добивается тишиной (до 5 с).
- `seq` обнуляется на каждом новом TCP-соединении, как и требует протокол.
- Переподключение — раз в 3 с; кадры, которые не удалось отправить, отбрасываются,
  запись при этом не «сжимается» по времени.
- После перезагрузки `first_sample` начинается с нуля — сервер это детектирует и
  открывает новый сегмент.

## Замечания

- Пины заданы в `include/config.h`. При переносе на другую плату проверяйте
  занятые выводы (table «Плата» выше): на S3 с octal-PSRAM нельзя трогать 26–37.
- Прошивка использует legacy-драйвер I2S (`driver/i2s.h`), который есть в
  arduino-esp32 2.x (в проекте установлен 2.0.17). При переходе на ядро 3.x
  потребуется переписать `audio_source.cpp` на `driver/i2s_std.h`.
