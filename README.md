# Radio — Si4703 + PCM1808 → radio-record-server

Прошивка ESP32: тюнер Si4703 отдаёт аналоговый звук на АЦП PCM1808, ESP32 читает
поток по I2S и шлёт его кадрами на [radio-record-server](https://github.com/labintsev/radio-record-server)
(протокол `RDIO`, PCM s16le, порт 9100).

## Что где

| Файл | Назначение |
|------|------------|
| `include/config.h` | Wi-Fi, адрес сервера, пины, формат аудио |
| `src/audio_source.cpp` | I2S + преобразование 24 бита → 16 бит |
| `src/streamer.cpp` | TCP-соединение и 43-байтный заголовок кадра |
| `src/main.cpp` | Wi-Fi, тюнер, аудио-задача, статистика |

## Подключение PCM1808

Модуль PCM1808 без своего кварца — **слейв шины**: ESP32 генерирует MCLK 12.288 МГц,
BCK 3.072 МГц и LRCK 48 кГц (`I2S_ESP32_MASTER 1`).

| PCM1808 | ESP32 | Примечание |
|---------|-------|------------|
| VCC     | 5V    | на модуле стоит LDO, логика 3.3 В |
| GND     | GND   | общая земля, аналоговую часть — к тому же GND |
| BCK     | GPIO26 | вход тактирования битов |
| LRCK    | GPIO25 | вход словного синхросигнала (48 кГц) |
| DOUT    | GPIO33 | данные от АЦП |
| SCKI    | GPIO27 | MCLK 12.288 МГц (GPIO0 на этой плате не выведен, TX0/RX0 не подходят) |
| FMT     | GND   | формат I2S (Philips), не left-justified |
| MD0/MD1 | GND   | slave-режим, 24 бита |

Аналог: `LOUT`/`ROUT` тюнера → `LIN`/`RIN` модуля (если на модуле нет разделительных
конденсаторов — поставить 1 мкФ последовательно), провода от цифровой части держать
подальше от аналоговых.

Если у модуля есть собственный кварц и он мастер — поставьте
`#define I2S_ESP32_MASTER 0`, отключите провод MCLK, а MD0/MD1 переведите в master
(BCK/LRCK при этом станут выходами модуля).

## Почему 48 кГц / стерео

От кварца 12.288 МГц PCM1808 умеет 256/384/512 fs → 48/32/24 кГц, но не 16 кГц.
Сервер по умолчанию ждёт 16 кГц моно, поэтому его нужно запускать с теми же
параметрами, что и прошивка:

```powershell
python -m radio_record --port 9100 --output recordings --sample-rate 48000 --channels 2
```

Поток — 192 кБ/с (≈1.5 Мбит/с), это нормально для Wi-Fi в локальной сети.

## Проверка без АЦП

В `include/config.h` выставить `AUDIO_SOURCE_TEST_TONE 1` — прошивка начнёт слать
синус 1 кГц вместо I2S. Удобно проверить путь «ESP32 → сервер» до подключения PCM1808.

## Диагностика I2S

При старте прошивка измеряет частоты на линиях (счётчик импульсов PCNT) и печатает:

```
[i2s] BCK 3072000 Гц, LRCK 48000 Гц
[i2s] фактическая fs 48000 Гц, 64 бит/кадр
```

Как читать:

| Вывод | Что это значит |
|-------|----------------|
| `BCK 0 Гц, LRCK 0 Гц` | тактирования нет: PCM1808 в slave-режиме, не подключён, или неверные пины |
| `LRCK 32000/24000/96000` | у модуля другой делитель/кварц — поправить `SAMPLE_RATE` и `--sample-rate` сервера |
| кадры идут, `пик 0` | DOUT не подключён, АЦП молчит или нет сигнала с тюнера |
| кадры идут, `пик > 0`, но `отправлено 0` | проблема сети/сервера (см. строки `[net]`) |

`[stat]` раз в 5 секунд показывает кадры/с, пиковый уровень последнего кадра, RSSI и
свободную память; при отсутствии данных печатается отдельная подсказка.

## Что происходит при обрывах

- `first_sample` растёт монотонно всё время работы, поэтому пауза при переподключении
  выглядит для сервера как пропуск и добивается тишиной (до 5 с).
- `seq` обнуляется на каждом новом TCP-соединении, как и требует протокол.
- Переподключение — раз в 3 с; кадры, которые не удалось отправить, отбрасываются,
  запись при этом не «сжимается» по времени.
- После перезагрузки `first_sample` начинается с нуля — сервер это детектирует и
  открывает новый сегмент.

## Замечания

- `GPIO12` (reset Si4703) — strapping-пин, который влияет на напряжение флеша при
  старте. Если плата иногда не грузится, перенесите reset на свободный GPIO
  (например, 27) и поправьте `PIN_TUNER_RESET`.
- Прошивка использует legacy-драйвер I2S (`driver/i2s.h`), который есть в
  arduino-esp32 2.x (в проекте установлен 2.0.17). При переходе на ядро 3.x
  потребуется переписать `audio_source.cpp` на `driver/i2s_std.h`.
